2. SCOPE OF STAGE 4.4 & POLLING-ONLY CONFIGURATION
--------------------------------------------------------------------------------
1. Official MyStars FaaS v1 REST API verification (`https://api.mystars.tg/v1`):
   - Verified official endpoints only (no invented endpoints):
     * `GET /v1/currencies`
     * `GET /v1/products`
     * `GET /v1/pricing`
     * `POST /v1/recipients/check`
     * `POST /v1/orders` (idempotent via `Idempotency-Key`, `callback_url` intentionally omitted)
     * `GET /v1/orders/{order_id}` (authoritative polling endpoint)
     * `POST /v1/orders/{order_id}/cancel`
     * `GET /v1/orders`
2. Exclusive Polling mode for MyStars:
   - `MYSTARS_API_KEY` remains required for automated fulfillment.
   - `MYSTARS_WEBHOOK_SECRET` and `MYSTARS_CALLBACK_URL` are strictly optional and unused; all startup and runtime dependencies on them have been removed.
   - Removed `POST /webhook/mystars`, `handleMyStarsWebhookRequest`, and `FulfillmentService.processMyStarsWebhook`.
   - `MyStarsClient.createOrder()` omits `callback_url` so order tracking relies exclusively on `GET /v1/orders/{order_id}`.
3. Persistence of external MyStars order state & P&L:
   - Persists `mystarsOrderId`, `mystarsOrderStatus`, `externalExecutionReference`, `mystarsPayToAddress`, `mystarsPaymentMemo`, `mystarsPaymentAmountUsdt`, `mystarsPurchaseTx`, `mystarsFailureReason`, `mystarsExpiresAt`, `mystarsLastPolledAt`, `mystarsPollAttempts`, `mystarsLastPollError`, `mystarsWholesaleCostUsdt`, `mystarsCostUsdCents`, `tonNetworkFeeUsdCents`, and `netProfitUsdCents`.
4. Anti-duplicate delivery & idempotency guarantees:
   - Deterministic `Idempotency-Key: fulfill_${order.orderId}` on `POST /v1/orders`.
   - Pre-check for existing `mystarsOrderId` before order creation (polls `GET /v1/orders/{id}` instead of creating a duplicate order).
   - Per-order in-flight polling lock (`inFlightMyStarsPollOrders`) + recovery pass mutex (`isRecoveryPassRunning`).
   - Atomic Firestore transactions in `initiateFulfillment`, `completeOrder`, and `markOrderFulfillmentFailedPermanent` prevent duplicate completion, duplicate ledger writes, and duplicate buyer/admin notifications.
5. Error, timeout, and rate-limit resilience:
   - Configurable HTTP timeout via `AbortController` (`MYSTARS_REQUEST_TIMEOUT_MS`, default 15,000 ms) producing retryable `MyStarsTransportError`.
   - Bounded retry on transient `GET` network/5xx errors in `MyStarsClient`.
   - RFC 7231 `Retry-After` parsing (both numeric seconds and HTTP-date strings) via `parseRetryAfterSeconds()`.
   - Distinct handling of HTTP `429 general` (retryable; sets global polling cooldown `mystarsPollCooldownUntilMs` without failing orders) vs HTTP `429 order_cap` (non-retryable on `POST /v1/orders`; prevents tight retry loops).
   - Transient polling errors (timeouts / HTTP 5xx / 429) preserve `fulfillmentStatus: 'processing'` and record `mystarsLastPollError` so the next tick retries cleanly.
6. Automatic continuation after bot/server restart:
   - All unfinished orders (`fulfillmentStatus === 'paid'` and `fulfillmentStatus === 'processing'` with `mystarsOrderId`) are persisted in Firestore.
   - On server startup, `FulfillmentService.startRecoveryWorker(() => botManager.getBotInstance(), config.mystarsPollIntervalMs)` runs an immediate initial pass of `recoverPendingFulfillments()` -> `pollMyStarsOrders()` and continues polling every `MYSTARS_POLL_INTERVAL_MS` (default 15,000 ms).
7. CryptoBot & xRocket Production Go-Live:
   - Pre-checkout recipient validation (`POST /v1/recipients/check`) before order creation, invoice creation, and internal balance deduction.
   - Background invoice reconciliation (`PaymentService.reconcilePendingOrderPayments()` + `balanceService.reconcilePendingTopUps()`).
   - Admin balance compensation (`allowExternalGatewayCompensation: true`) with double-refund protection.

4. FINDINGS, RISKS & RESOLUTIONS
--------------------------------------------------------------------------------
[FINDING-44-01] CRITICAL (RESOLVED) — Exclusive Polling Without Public Webhook Dependency
- Issue: Requiring `MYSTARS_WEBHOOK_SECRET` and `MYSTARS_CALLBACK_URL` forced deployments to expose a public MyStars webhook endpoint and manage secret rotation even when running Telegram in polling mode or behind restricted ingress.
- Resolution: Removed `/webhook/mystars` and `callback_url` transmission completely. Order lifecycle tracking now runs exclusively via official `GET /v1/orders/{order_id}` polling using only `MYSTARS_API_KEY`.

[FINDING-44-02] HIGH (RESOLVED) — Rate-Limit Cooldown & Timeout Protection in Polling Loop
- Issue: Naive polling loops can fail orders on transient network timeouts / HTTP 503 or flood MyStars during HTTP 429 rate limits.
- Resolution: Implemented `MyStarsTransportError` timeout handling, `parseRetryAfterSeconds()` (numeric & HTTP-date), global `mystarsPollCooldownUntilMs` backoff on `429 general`, and non-retryable handling of `429 order_cap`. Transient errors never fail an in-flight `processing` order.

[FINDING-44-03] HIGH (RESOLVED) — Duplicate Delivery & Restart Safety
- Issue: Overlapping polling ticks or container restarts could re-submit `POST /v1/orders`, double-complete an order, or re-notify buyers.
- Resolution: Enforced deterministic `Idempotency-Key`, pre-check for existing `mystarsOrderId`, per-order polling mutex (`inFlightMyStarsPollOrders`), atomic Firestore transactions (`completeOrder`, `markOrderFulfillmentFailedPermanent`), and immediate startup recovery (`recoverPendingFulfillments`).

[FINDING-44-04] MEDIUM (RESOLVED) — Pricing Schema Type Alignment in Automated Tests
- Issue: `tsc --noEmit` flagged `total_usdt` on `MyStarsPricingQuote` in `S44-01` where official MyStars FaaS v1 uses `amount` and `fee.total`.
- Resolution: Aligned `S44-01` mock and assertions strictly to the official `MyStarsPricingQuote` contract.
